## 1. 背景与目标

开发一个基于 B/S 架构的**本地**语音识别 Web 系统。用户通过浏览器麦克风录音或上传音频文件，系统使用部署在本机的开源 ASR 模型，将中文普通话或英文语音转换为文字，并在页面上展示识别结果、音频时长和处理耗时。

核心目标：

1. 全流程本地推理，运行期不调用任何云端 ASR 服务。
2. 在普通开发电脑的 CPU 上可运行，不强制 NVIDIA GPU / CUDA。
3. 安装简单，统一使用 `pip` + `uvicorn` 启动，不依赖 Docker、Node.js、数据库或外部 ffmpeg。
4. 异常场景有明确提示，页面不崩溃，失败后可重试。
5. 在必做功能稳定的基础上，提供近实时语音识别（F6）作为加分项。

### 1.1 需求理解

对原始需求做四层归纳，避免只按页面功能实现而漏掉约束：

1. **系统形态**：B/S、单机、单用户。浏览器只负责采集与展示，识别全部在 `127.0.0.1` 后端完成。
2. **业务能力**：中文普通话与英文的语音转文字；语言由用户选择，不做翻译，不要求说话人识别、降噪或历史记录。
3. **工程约束**：Python 3.12、FastAPI、原生 HTML/CSS/JS；CPU 可运行；`pip` 安装；不使用 Docker、Node.js、数据库、云端 ASR 或系统 ffmpeg。
4. **交付要求**：必做 F1–F5、加分 F6、`pytest` 可离线运行、真实模型测试与样例音频、五份文档及 OpenCode 开发过程记录。

由此确定的核心边界是：**录音 60 秒、上传 10 MB、上传不限时长、推理串行、模型懒加载、运行期全程本地**。

### 1.2 功能拆分

| 功能域 | 需求编号 | 前端职责 | 后端职责 | 主要验证 |
| --- | --- | --- | --- | --- |
| 录音 | F1 | 权限申请、MediaRecorder、60 秒计时与自动停止 | 解码、`source=recording` 时长校验 | 浏览器 E2E、`test_errors` |
| 上传 | F2 | 文件选择/拖放、大小与扩展名预检 | 分块读取 10 MB、PyAV 解码 | `test_audio`、`test_errors` |
| 识别 | F3 | 语言选择、请求参数 | faster-whisper small、CPU int8、VAD | 真实模型测试、`test_transcribe_api` |
| 展示 | F4 | 状态机、结果/时长/耗时、复制 | 返回文本、语言、时长、耗时、分段 | 浏览器 E2E、`test_frontend_flow` |
| 异常 | F5 | 权限/网络/服务错误提示与恢复 | 统一 `detail + code` 错误响应 | `test_errors`、浏览器异常场景 |

### 2.2 明确不做

- 用户登录、权限管理、多租户。
- 数据库、识别历史记录、对象存储。
- 说话人识别、声纹分析、音频降噪算法。
- 语音翻译、文字转语音（TTS）。
- 模型训练 / Fine-tuning。
- 分布式部署、多用户高并发、商业级实时字幕。
- 手机端适配、HTTPS/域名部署。

## 3. 术语

| 术语 | 说明 |
| --- | --- |
| ASR | Automatic Speech Recognition，自动语音识别 |
| 录音模式 | 浏览器采集麦克风音频后提交识别 |
| 上传模式 | 用户选择本地音频文件后提交识别 |
| 实时模式 | 录音过程中分片发送音频，持续返回临时识别文本 |
| 处理耗时 | 服务端解码 + 模型推理耗时，不含首次下载/加载模型 |
| 无语音 | 音频可解码，但 VAD 未检测到有效语音 |

## 4. 用户角色与典型流程

系统只有一个角色：**本机使用者**。

### 4.1 录音识别流程

1. 打开 `http://127.0.0.1:8000`。
2. 选择识别语言（中文 / English / 自动检测）。
3. 点击“开始录音”，浏览器请求麦克风权限。
4. 页面显示录音状态、实时计时和 60 秒上限。
5. 点击“停止录音”或达到 60 秒自动停止。
6. 页面显示“识别中”，提交音频到后端。
7. 识别完成后展示文本、音频时长、处理耗时和识别语言。
8. 用户可复制文本，或直接开始下一次录音。

### 4.2 上传识别流程

1. 选择识别语言。
2. 选择或拖入音频文件。
3. 前端校验大小/扩展名后，点击“上传并识别”。
4. 后端解码并识别，页面展示结果。
5. 可继续上传下一个文件。

### 4.3 实时识别流程（加分）

1. 勾选“实时识别（实验）”。
2. 点击开始录音，页面持续显示临时识别文本。
3. 点击停止后，服务端对完整音频做最终识别，页面用最终文本覆盖临时文本。

## 5. 功能需求与验收标准

### F1 浏览器麦克风录音

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F1-1 | 请求麦克风权限 | 首次点击开始录音时触发权限请求；拒绝后页面显示原因且不崩溃 |
| F1-2 | 开始/停止录音 | 两个操作均有明确按钮状态；停止后才提交普通录音识别 |
| F1-3 | 状态与时长 | 录音中显示“录音中”、已录秒数，并显示 60 秒进度 |
| F1-4 | 最长 60 秒 | 达到 60 秒自动停止；前端禁用继续录制；后端对 `source=recording` 再次校验 |
| F1-5 | 再次录音 | 一次识别完成后可直接开始新录音，无需刷新页面 |
| F1-6 | 设备异常 | 无麦克风、设备被占用、非安全上下文均有明确提示 |

### F2 音频文件上传

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F2-1 | 支持 WAV | `.wav`（PCM/浮点，任意常见采样率/声道）可识别 |
| F2-2 | 支持浏览器录音格式 | 支持 Chrome/Edge 的 WebM-Opus；同时兼容 OGG、MP3、M4A 等可解码格式 |
| F2-3 | 共用识别逻辑 | 上传和录音调用同一个 `POST /api/transcribe` 与同一套音频流水线 |
| F2-4 | 无效文件提示 | 空文件、损坏文件、不支持格式返回 4xx 与可理解提示 |
| F2-5 | 大小限制 | 单文件最大 10 MB；超出返回 413，且不将完整文件读入内存 |
| F2-6 | 时长 | 上传文件不设置业务时长上限；提供可选配置 `MAX_AUDIO_SECONDS`（默认 0，不限制） |

### F3 本地中英文语音识别

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F3-1 | 中文识别 | `language=zh` 输出中文文本 |
| F3-2 | 英文识别 | `language=en` 输出英文文本 |
| F3-3 | 语言选择 | 页面提供中文/英文选择，并在请求中传递 |
| F3-4 | 结果返回 | 识别文本通过 JSON 返回页面 |
| F3-5 | 连续识别 | 单次识别结束后可继续下一次识别 |
| F3-6 | 自动语言检测（加分） | `language=auto` 时由模型自动检测中英文，返回检测结果 |
| F3-7 | 本地模型 | 运行期不访问云端 ASR；模型权重首次可联网下载，之后可离线运行 |
| F3-8 | CPU 推理 | 默认 `device=cpu`、`compute_type=int8`，无需 GPU/CUDA |
| F3-9 | 不做翻译 | 中文语音输出中文，英文语音输出英文，不进行跨语言翻译 |

### F4 识别结果展示

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F4-1 | 当前语言 | 页面始终显示当前选择的识别语言 |
| F4-2 | 状态展示 | 空闲、请求权限、录音中、识别中、完成、失败状态清晰可见 |
| F4-3 | 文本展示 | 识别完成后展示完整文本；空结果有明确提示 |
| F4-4 | 时长与耗时 | 展示 `duration_seconds` 与 `processing_seconds` |
| F4-5 | 过程反馈 | 识别期间按钮禁用并显示加载提示；超过 3 秒追加“首次运行可能较慢”说明 |
| F4-6 | 复制 | 一键复制识别文本，成功/失败均有反馈 |
| F4-7 | 模型信息 | 页面可显示当前模型名称与就绪状态（来自 `/api/status`） |

### F5 异常处理

| 场景 | 预期行为 | HTTP / 错误码 |
| --- | --- | --- |
| 用户拒绝麦克风权限 | 提示“麦克风权限被拒绝”，不崩溃，可重试 | 前端处理 |
| 未检测到麦克风 | 提示“未检测到可用麦克风” | 前端处理 |
| 上传空文件 | 拒绝处理并提示文件为空 | 400 `empty_file` |
| 文件损坏/无法解码 | 拒绝并提示无法解码 | 400 `decode_failed` |
| 文件格式不支持 | 明确提示支持格式 | 400 `unsupported_audio` |
| 文件超过 10 MB | 拒绝处理 | 413 `file_too_large` |
| 缺少 file 字段 | 返回参数错误 | 422 `validation_error` |
| 非法语言 | 提示仅支持 `zh` / `en` / `auto` | 400 `invalid_language` |
| 录音超过 60 秒 | 前端自动停止；后端对 `source=recording` 拒绝超限 | 400 `recording_too_long` |
| 模型加载失败 | 返回可理解信息，提示执行模型下载脚本 | 503 `model_unavailable` |
| 推理过程异常 | 页面提示失败，允许重试 | 500 `inference_failed` |
| 模型推理超时 | 预留 504 错误码；默认不启用超时，长音频请耐心等待或设置可选时长限制 | 504 `inference_timeout`（预留） |
| 音频无有效语音 | 不崩溃，返回空文本并标记 `no_speech` | 200 |
| 识别中重复点击 | 按钮禁用，前端阻止重复请求 | 前端处理 |
| 网络中断/服务未启动 | 显示连接失败提示 | 前端处理 |

统一错误响应格式：

```json
{
  "detail": "无法解码该音频文件，请确认文件未损坏。",
  "code": "decode_failed"
}
```

### F6 近实时语音识别（加分）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| F6-1 | 持续采集 | 录音期间通过 Web Audio 采集 PCM，分片发送到后端 |
| F6-2 | 分片传输 | 使用 WebSocket 二进制帧传输 16 kHz、16-bit、单声道 PCM |
| F6-3 | 增量结果 | 录音过程中持续收到 `partial` 消息并更新页面 |
| F6-4 | 最终结果 | 停止后收到 `final` 消息，使用完整音频重新识别并覆盖临时结果 |
| F6-5 | 失败降级 | 实时模式失败时提示错误；可切回普通录音模式重新识别 |
| F6-6 | 限制 | 实时录音同样限制 60 秒；不承诺商业级延迟 |

## 6. 接口需求

### 6.1 `GET /health`

健康检查，不触发模型加载。

- 200：

```json
{ "status": "ok" }
```

### 6.2 `GET /api/status`（扩展接口）

用于页面展示模型与限制信息，不改变必做接口契约。

- 200：

```json
{
  "status": "ok",
  "model": "small",
  "device": "cpu",
  "compute_type": "int8",
  "model_loaded": false,
  "model_ready": false,
  "offline": false,
  "max_upload_mb": 10,
  "max_recording_seconds": 60,
  "error": null
}
```

### 6.3 `POST /api/transcribe`

`multipart/form-data`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| file | File | 是 | 音频文件，最大 10 MB |
| language | String | 是 | `zh` / `en`；`auto` 为加分项 |
| source | String | 否 | `recording` / `upload`，默认 `upload`；仅用于录音 60 秒校验 |

成功 200：

```json
{
  "text": "你好，欢迎使用语音识别系统。",
  "language": "zh",
  "duration_seconds": 5.2,
  "processing_seconds": 1.8,
  "model": "small",
  "requested_language": "zh",
  "no_speech": false,
  "segments": [
    { "start": 0.0, "end": 5.1, "text": "你好，欢迎使用语音识别系统。" }
  ]
}
```

字段说明：

- `text`：识别文本；无语音时为空字符串。
- `language`：本次实际识别语言（`auto` 时为检测结果）。
- `duration_seconds`：解码后音频实际时长，单位秒。
- `processing_seconds`：解码 + 推理耗时，不含模型下载和加载。
- `model`、`requested_language`、`no_speech`、`segments`：扩展字段，不破坏必做契约。

错误：非法参数/文件返回 4xx；模型不可用或推理失败返回 5xx，响应包含 `detail` 与 `code`。

### 6.4 `GET /`

返回 `static/index.html`，页面资源全部本地化，不依赖 CDN。

### 6.5 `WS /ws/transcribe`（扩展接口）

- 连接参数：`?language=zh|en|auto`。
- 文本控制消息：

```json
{ "type": "start", "language": "zh" }
{ "type": "stop" }
```

- 二进制消息：16 kHz、16-bit 小端、单声道 PCM 分片。
- 服务端消息：

```json
{ "type": "ready", "sample_rate": 16000 }
{ "type": "partial", "text": "已识别的累计文本", "duration_seconds": 3.2 }
{ "type": "final", "text": "最终文本", "language": "zh", "duration_seconds": 10.1, "processing_seconds": 2.3 }
{ "type": "error", "code": "inference_failed", "message": "识别失败，请重试。" }
```

### 6.6 `GET /v1/models`（工具兼容，非业务需求）

OpenCode 内置的 vLLM 本地发现会探测 `http://127.0.0.1:8000`，先请求 `/health`，再请求 `/v1/models`。本项目不是 LLM 服务，因此该路由只返回空模型列表，避免探测产生误导性的 404：

```json
{ "object": "list", "data": [] }
```

该接口不参与业务验收，不出现在 `/docs` 中，也不代表系统提供任何聊天模型能力。

## 7. 非功能需求

### 7.1 性能

- 10 秒左右的中文/英文音频，在普通 4 核以上 CPU 上目标处理时间不超过约 30 秒；不承诺硬实时。
- 页面在识别期间必须持续显示状态，不允许无反馈等待。
- 实时模式以 2–5 秒级增量结果为目标，不承诺毫秒级延迟。

### 7.2 离线与隐私

- 音频只发送到本机 `127.0.0.1` 后端，不上传第三方。
- 模型权重可首次联网下载，之后断网可识别。
- 不写入数据库，不持久化音频；临时内存数据在请求结束后释放。

### 7.3 兼容性

- 统一复现环境：Windows 11 x64、Python 3.12、普通 CPU。
- 浏览器：Chrome / Edge 最新稳定版，通过 `http://127.0.0.1:8000` 访问。
- 开发环境可为 Windows / macOS / Linux，但交付验证以 Windows 为准。

### 7.4 可维护性

- 后端模块分层：配置、音频、ASR、API、实时会话。
- 模型通过接口抽象，测试可注入 Fake 引擎。
- 所有依赖通过 `requirements.txt` 固定版本。
- 默认 `pytest` 不下载模型、不访问麦克风。

### 7.5 安全

- 上传文件只保存在内存中，不落盘，不使用用户文件名拼接路径。
- 限制上传大小，分块读取，避免内存耗尽。
- 不提供目录浏览；静态资源限定在 `static/`。
- 仅监听 `127.0.0.1`，默认不对外网开放。

## 8. 约束、假设与边界条件

### 8.1 必要假设

| 编号 | 假设 | 不成立时的影响 |
| --- | --- | --- |
| A1 | 单机、单用户、通过 `127.0.0.1` 访问，不做登录与鉴权 | 多用户并发、公网部署不在本次范围 |
| A2 | 使用最新版 Chrome / Edge，且页面处于 localhost 安全上下文 | 其他浏览器或非安全上下文可能无法录音 |
| A3 | 设备存在可用麦克风，用户会授予权限 | 无设备/拒绝权限时只提供提示，不静默失败 |
| A4 | 首次可联网下载模型，或已手动把权重放入 `models/` | 离线且无权重时返回 `503 model_unavailable` |
| A5 | 音频以单人、连续语音为主，允许少量环境噪声 | 音乐、多人重叠、强噪声的准确率不作承诺 |
| A6 | 上传文件完整且容器可解析 | 损坏、截断、伪装扩展名的文件会被 4xx 拒绝 |
| A7 | 用户选择的语言与音频主要语言一致；`auto` 仅作实验 | 语言选错时识别质量下降，不属于系统故障 |
| A8 | 运行期只访问本机服务，不依赖云端 ASR、CDN 或数据库 | 断网不影响已下载模型的识别 |

### 8.2 边界条件

| 编号 | 输入 / 场景 | 边界定义 | 预期行为 |
| --- | --- | --- | --- |
| B1 | 录音时长 | `≤ 60.0 s` 接受；`60.0–60.5 s` 受 0.5 s 解码容差影响可能接受；`> 60.5 s` 拒绝 | `400 recording_too_long`；前端在 60 s 主动停止 |
| B2 | 上传大小 | `≤ 10 MB` 接受；`> 10 MB` 拒绝 | `413 file_too_large`；分块读取，不整文件缓存 |
| B3 | 上传时长 | 默认不限制；设置 `MAX_AUDIO_SECONDS > 0` 后，`> 限制 + 0.5 s` 拒绝 | `400 audio_too_long` |
| B4 | 空文件 | 0 字节 | `400 empty_file` |
| B5 | 损坏 / 非音频文件 | 无法打开容器或没有音频流 | `400 unsupported_audio` 或 `400 decode_failed` |
| B6 | 语言参数 | `zh` / `en` / `auto`，忽略大小写与首尾空白 | 其他值 `400 invalid_language` |
| B7 | 来源参数 | `recording` / `upload`，缺省 `upload` | 其他值 `400 invalid_source` |
| B8 | 静音音频 | 峰值 `< 1e-3` | `200`、`text=""`、`no_speech=true`，不调用模型 |
| B9 | 极短音频 | 可解码但不足一个词，例如 0.2 s | 正常返回；可能为空文本，不报错 |
| B10 | 10 MB 内的超长压缩音频 | 默认没有业务时长上限 | 请求会等待较久；可用 `MAX_AUDIO_SECONDS` 防护 |
| B11 | 实时 PCM 分片 | 16 kHz / 16-bit / 单声道小端；奇数字节末位丢弃 | 未 `start` 收到音频 → `not_started` |
| B12 | 实时录音时长 | 超过 `60.5 s` | WebSocket `error: recording_too_long` |
| B13 | 重复点击 | 录音、识别、上传期间按钮禁用 | 前端阻止重复请求 |
| B14 | 并发识别 | 单模型、推理加锁、串行排队 | 不承诺多用户并发吞吐 |
| B15 | 模型缺失 / 加载失败 | 本地无权重、离线模式或加载异常 | `503 model_unavailable`，提示下载脚本 |
| B16 | 推理异常 | 模型内部抛出异常 | `500 inference_failed`，页面可重试 |
| B17 | 网络 / 服务不可用 | 页面无法连接后端 | 前端显示连接失败，不清空上一次结果 |
| B18 | 非安全上下文 | `navigator.mediaDevices` 不可用 | 提示通过 `http://127.0.0.1:8000` 访问 |

### 8.3 环境与实现约束

1. Python 版本固定为 **3.12**；本机若默认 Python 为其他版本，需显式使用 3.12 创建虚拟环境。
2. 模型使用 `faster-whisper` 的 `small` 多语言模型，CPU `int8` 推理；模型约 460 MB。
3. 首次识别或执行下载脚本时需要互联网；之后设置离线模式也可运行。
4. 不依赖系统 ffmpeg，音频解码使用 PyAV wheel 内置库。
5. 单进程、单模型实例、推理串行，适合本机单用户使用；不保证并发吞吐。
6. 录音上限 60 秒；上传仅限制 10 MB，不限制时长（可选配置开启时长保护）。
7. 自动语言检测为加分项，准确率不作为必做验收条件。
8. 页面不做移动端专门适配。
9. 浏览器录音格式以 Chrome/Edge 的 `audio/webm;codecs=opus` 为主，其他格式尽力兼容。

## 10. 风险与待确认项

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 首次下载模型慢或被网络阻断 | 首次识别失败 | 提供 `python -m app.scripts.download_model`；错误信息给出操作指引 |
| CPU 性能差异大 | 识别耗时超出预期 | 默认 `small + int8 + beam_size=1`；可配置切换 `base` |
| 压缩格式时长不可控 | 超长音频等待久 | 10 MB 限制；可选 `MAX_AUDIO_SECONDS`；页面持续反馈 |
| 实时分片切断词语 | 临时文本抖动/重复 | 分片重叠 + 文本去重；最终以整段识别结果为准 |
| 浏览器兼容差异 | 无法录音 | 以 Chrome/Edge 为准；提示使用最新版浏览器和 localhost |
| Windows 音频解码库缺失 | 上传格式失败 | PyAV wheel 自带 FFmpeg；WAV 作为最低保障 |
| 开发工具端口探测 | 日志出现无关的 `/v1/models` 请求 | 仅影响日志可读性；提供空模型兼容响应，不影响业务 |
