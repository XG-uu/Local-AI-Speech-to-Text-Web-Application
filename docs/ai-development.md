## 1. 概述

本项目使用 OpenCode 作为 AI 编程助手完成从需求分析到实现、测试和文档的全流程。AI 负责提出方案、生成初稿、编写测试和辅助定位问题；开发者负责确认业务边界、拍板关键技术决策、实际运行验证，并对最终交付质量负责。

开发过程坚持三条原则：

1. **先文档后代码**：先写清需求、接口与错误码，再实现，减少返工。
2. **默认测试不依赖重资源**：`pytest -q` 不下载模型、不访问麦克风，真实测试单独执行。
3. **所有 AI 产物必须可验证**：每条需求都有对应的自动化测试或手工验收记录。

## 4. 由开发者确认的重要技术决策

以下决策由开发者结合需求、实测结果和运行环境拍板；OpenCode 负责给出候选方案、对比依据和验证命令。

| 决策 | 备选方案 | 最终选择与理由 |
| --- | --- | --- |
| ASR 模型 | base / small / medium；sherpa-onnx；FunASR；whisper.cpp | **faster-whisper small + CPU int8**：单模型覆盖中英文，pip 安装免编译，实测 8.7 s 中文约 1.55 s |
| 音频解码 | 系统 ffmpeg / PyAV / 纯标准库 | **PyAV 为主，标准库 WAV 兜底**：wheel 自带 FFmpeg，覆盖 WebM/Opus，且不要求用户安装 ffmpeg |
| 上传限制 | 限制时长 / 限制大小 / 两者都限 | **只限 10 MB，不限时长**：严格符合需求；另提供 `MAX_AUDIO_SECONDS` 可选保护 |
| 录音限制 | 仅前端 / 仅后端 / 双重 | **前端 60 s 自动停止 + 后端 `source=recording` 校验**：体验与契约双重保障 |
| 实时传输 | MediaRecorder 分片 / WebSocket 原始 PCM | **WebSocket + 16 kHz PCM**：WebM 分片通常不能独立解码，PCM 更稳定 |
| 测试策略 | 默认加载真实模型 / 注入 Fake | **默认 Fake，真实模型测试用 `RUN_REAL_ASR=1` 隔离**：不拖慢日常回归、不强制下载 460 MB |
| 模型加载 | 启动即加载 / 首次请求懒加载 | **懒加载**：`/health` 快速可用，`processing_seconds` 不含加载时间 |
| 时长边界 | 严格比较 / 留容差 | **0.5 s 容差**：吸收编码补帧、时间戳与重采样误差，前端仍按 60 s 停止 |
| 工具探测 | 忽略 404 / 伪造 LLM / 空模型响应 | **空模型响应**：只声明“没有聊天模型”，不伪造 `/v1/chat/completions` |
| 文档位置 | 根目录 / `docs/` | **正式文档统一放 `docs/`**，README 留在根目录并统一导航 |

## 5. 遇到的问题及 AI 协助处理

| 问题 | 现象 | 定位与处理 | 验证 |
| --- | --- | --- | --- |
| PyAV 版本差异 | `AudioResampler.resample(None)` 在不同版本行为不同 | 对 flush 做兼容捕获；保留标准库 WAV 兜底 | 音频测试通过 |
| 时长边界误判 | 1 s 音频未触发 0.5 s 限制 | 明确 0.5 s 解码容差，测试改用 2 s 音频；生产限制仍为 60 s | `test_errors`、`test_audio` |
| 中文段拼接空格 | 按空格拼接导致中文出现空格 | 保留 Whisper segment 原始文本，直接拼接 | 真实中文识别正确 |
| 422 响应结构不一致 | FastAPI 默认校验错误与其他错误格式不同 | 增加 `RequestValidationError` 处理器，统一 `detail + code` | 缺文件/缺语言测试 |
| PowerShell 编码 | 中文脚本被 5.1 误读，报“字符串缺少终止符” | 脚本保存为 UTF-8 with BOM | 样例生成成功 |
| 模型镜像失败 | `hf-mirror.com` 返回 500，下载失败 | 切换官方端点并配置本机代理；README 提供手动下载兜底 | 模型下载成功、真实测试通过 |
| 实时文本重复 | 重叠窗口导致边界重复 | `merge_text` 做最长后缀/前缀去重；最终以整段识别覆盖 | 实时单测与 E2E |
| 静音幻觉 | 无语音音频可能被模型“猜”出文字 | 峰值静音检测 + faster-whisper VAD 双重过滤 | 静音返回空文本 |
| 端口探测 404 | 日志周期性出现 `GET /v1/models 404` | 记录请求头，定位为 OpenCode 内置 vLLM 发现；增加空模型兼容路由 | 复测 200，空列表 |
| 虚拟音频循环 | 60 s E2E 的文本重复 | 测试环境使用循环音频所致，非产品缺陷；记录到测试报告 | 自动停止与耗时验证通过 |

## 6. 如何确认 AI 生成的代码满足业务需求

采用“需求追踪 + 分层测试 + 真实环境验收”的方式，而不是只看代码是否能运行：

1. **需求追踪**：`docs/requirements.md` 为 F1–F6 建立编号；`docs/test-report.md` 3.5 给出需求到用例的覆盖矩阵。
2. **默认回归**：`python -m pytest -q` → `49 passed, 3 skipped in 0.40s`，且不下载模型、不访问麦克风、不联网。
3. **真实模型**：`RUN_REAL_ASR=1 pytest -m real_asr` → `3 passed, 49 deselected`；中文与英文样例文本均正确，处理耗时约 1.5 s。
4. **接口契约**：逐项验证 200/400/413/422/500/503、`detail + code`、10 MB 分块、60 s 校验、静音 `no_speech`。
5. **浏览器 E2E**：Chrome + 虚拟音频设备真实点击录音、上传、实时、复制；另测权限拒绝、损坏文件、60 s 自动停止。
6. **离线验证**：`ASR_OFFLINE=1` + `HF_HUB_OFFLINE=1` 启动后仍可识别，确认运行期无云端依赖。
7. **人工代码审查**：检查上传不落盘、路径不拼接用户文件名、推理不阻塞事件循环、错误不泄露堆栈。
8. **结果复核**：所有测试输出、真实识别文本、E2E 关键状态均记录在 `docs/test-report.md` 与 OpenCode 过程记录中。

## 8. 如果继续优化，优先改进什么

| 优先级 | 改进项 | 原因 |
| --- | --- | --- |
| P0 | 原生流式 ASR（如 sherpa-onnx 流式模型）或更细粒度增量解码 | 当前 60 s 音频约需 56 s，实时模式仍是“分片重识别”；流式可显著降低等待并减少临时文本抖动 |
| P0 | 标点、数字与专有名词后处理（ITN） | Whisper 中文常输出半角标点，数字/单位格式不统一 |
| P1 | 请求取消、推理超时与队列 | 长音频或连续请求会占满单模型；需要可取消、可观测的队列 |
| P1 | 模型预热与热切换 | 首次识别有加载等待；切换 base/small 需要重启 |
| P1 | 并发与资源限制 | 当前单用户串行；多用户需要队列、限流与内存保护 |
| P1 | 降噪与 VAD 调参 | 真实房间噪声下准确率与断句仍可提升 |
| P2 | 识别历史（可选数据库）、导出 | 当前明确不做，但实际使用中常被需要 |
| P2 | GPU 自动选择、Docker/打包、HTTPS/鉴权 | 属于部署形态扩展，不是本次约束 |
| P2 | 移动端适配与可访问性 | 当前只保证桌面 Chrome/Edge |

如果只做一件事，优先做 **流式识别与长音频延迟优化**；它同时改善普通识别等待、实时预览质量和 60 秒上限体验。
